# Research: native Rust port of rebuildup.inbox (Issue #291)

Implementation + verification record for porting `plugins/inbox` from
TypeScript (Bun) to a committed native binary (Rust), per ADR-0035
(native plugin distribution) and ADR-0036 (native TUI runtime). Program
#286 / native-performance-baseline (#287) motivated the port; the
baseline numbers this doc compares against live in
`docs/research/native-performance-baseline.md`.

Verification host: macOS arm64 (Apple M5), herdr `0.9.5`
(`/Users/rebui/.local/share/mise/installs/herdr/0.9.5/herdr`). Linux and
Windows are **unverified** — `platforms = ["macos"]` in the manifest is
the honest scope until binaries for other targets exist and are verified.

## 1. What shipped

| piece | location | notes |
| --- | --- | --- |
| plugin binary | `plugins/inbox/bin/inbox` (~3 MB, committed, macOS arm64) | manifest argv is `./bin/inbox`; no Bun/toolchain needed at install or run time |
| CLI + hooks + watch + watch-pr | `plugins/inbox/src/{cli,hook,model,state,transitions,watchpr,pluginroot}.rs` | contract `herdr-plugins.inbox/v1` stable; version `0.8.0` |
| TUI | `plugins/inbox/src/{tui,tui_model}.rs` | contract `herdr-plugins.tui/v1`; in-process domain calls (no self-respawn) |
| shared socket client | `crates/herdr-client` | NDJSON RPC, session/socket resolution, atomic state-file helpers |
| shared TUI safety | `crates/tui` (`safety.rs`) | `sanitize_display`/`bound_text`/`BoundedBuffer` extracted per ADR-0036 boundary (app shell deferred until a second consumer) |
| TS implementation | deleted (`plugins/inbox/src/*.ts`, 7 retired test files) | recoverable at `0680de0~1` |

Manifest (`herdr-plugin.toml`) entrypoints, `[[actions]]`, `[[events]]`,
`[[panes]]`, and `[[startup]]` all run `./bin/inbox ...`. Sibling
plugins that delegated to inbox (`plugins/git/src/inbox.ts`,
`plugins/projects/src/inbox-source.ts`, `plugins/checkpoints/src/auto.ts`)
now resolve and spawn `bin/inbox` with a `bun src/cli.ts` fallback for
any not-yet-migrated checkout.

## 2. Contract parity evidence

- `tests/inbox-native.test.ts` — 19 spawn-based contract tests against a
  fake herdr socket (same NDJSON protocol the TS suite used): usage
  errors, organize verbs, filters, tracker links, stale-generation
  guards, capability incl. additive `command_metadata` (#263), non-TTY
  `tui` fallback, and TS-written `state.json` compatibility
  (`tests/fixtures/inbox-state-ts-v2.json`, generated by the retired TS
  code in the main checkout).
- `scripts/diff-inbox.ts` — fixture-driven TS↔Rust output-parity
  harness. `git archive`s `plugins/inbox` + `packages` at the pinned
  pre-removal commit (`0680de0~1` = `d5d74ce`), runs both
  implementations against the same fake socket and fresh state dirs,
  and deep-compares normalized stdout JSON, exit codes, and final
  `state.json`. Result: **30/30 checks identical**
  (usage-errors ×4, capability, organize-flow ×14, links-flow ×5,
  tui-fallback, plus per-scenario state parity). Documented
divergences, all intentional: `command_metadata` + `version` on
  `capability` (additive v0.8.0), and tmp-path/session-key
  canonicalization (`/var` → `/private/var`, scrubbed by the harness).
  Re-run: `bun scripts/diff-inbox.ts`.
- `bun run validate:fast` — 1435 pass / 0 fail.
- `cargo clippy`/`cargo fmt --check` — clean on `inbox`, `hoxay-tui`,
  `hoxay-herdr-client`.

## 3. Bugs found by the port (all fixed)

1. `watch --interval abc` silently defaulted to 60 s and reached the live
   socket; now an explicit invalid/non-positive value is a usage error
   (exit 2), absent flag still defaults to 60 s — mirrors `cli.ts`.
2. `herdr-client` `env_nonempty_opt` treated `--socket`/`--session`
   **values** as env-var names, so the flags were silently ignored.
3. TUI startup stalled ~2 s on terminals that never answer the
   cursor-position report (DSR `ESC[6n`): ratatui-core's
   `Terminal::clear()` queries `get_cursor_position()`. The clear was
   redundant after `EnterAlternateScreen`; removing it took PTY-probe
   `data_usable` from ~2015 ms to ~30 ms (debug build). See §5.
4. `bin/inbox` once produced `Killed: 9` on macOS after `cp` — a stale
   amfid/codesign assessment for the path; re-copying the identical
   bytes fixed it. If a committed binary ever fails this way, replace
   the file (do not chmod-in-place).

## 4. Isolated-session verification (np291)

Dedicated XDG/herdr session `np291`
(`XDG_CONFIG_HOME=/var/tmp/np291-herdr/config`, etc.; the user's live
sessions were never touched):

- `herdr plugin link plugins/inbox` — manifest parsed; `plugin list`
  shows all 8 actions, 2 event hooks, the `main` pane entrypoint,
  `[[startup]] reconcile`, `platforms=["macos"]`, `version 0.8.0`.
- Startup `reconcile` ran at server start; manual `inbox reconcile`
  returned a clean contract envelope.
- Pane-context verbs against a real pane (`w1:p1`): `settle`, `pin`,
  `archive`, `unarchive`, `snooze --until +1h`, `unpin`, `restore`,
  `order` — all emitted contract JSON and wrote
  `state/herdr/plugins/rebuildup.inbox/state.json` (v2 schema).
- `inbox hook` with `HERDR_PLUGIN_EVENT=pane.agent_status_changed` and
  `pane.closed` envelopes exited 0 against the real socket.
- `inbox tui` non-TTY fallback printed the plain list; PTY behavior
  covered by §5.
- `herdr plugin install rebuildup/hoxay-plugins/plugins/inbox --ref 291`
  — managed GitHub install resolved branch `291` → `c8155a0`; the
  installed `bin/inbox` ran `capability`/`list` against the np291
  session correctly.
- Generation switching / rollback: uninstall + `--ref
  0680de0ea169e65f7edb888949d1c2844eefc5a1` installed the earlier
  native generation (three generation dirs retained under
  `github-installations/`), its binary read the same `state.json`
  fine, and reinstalling `--ref 291` moved forward again —
  `plugin update rebuildup.inbox` then reported "already up to date".
- `herdr plugin disable`/`enable rebuildup.inbox` toggled cleanly;
  invocations fail with `plugin_disabled` while disabled (independent
  lifecycle per AGENTS.md §4).

Not exercised live: `watch-pr` against a real forge (covered by
contract tests with a stub `gh`), interactive TUI keys (PTY probe +
contract tests only — same evidence level as the TS implementation had).

## 5. Performance re-measurement (#287 baseline comparison)

Same host, same `np287` isolated session (16 panes, 2 workspaces —
agent-status reporters were not re-registered after the session
restore, so attention counts differ from baseline; pane count and socket
path are identical), same harness (`scripts/perf/measure.ts`,
`scripts/perf/tui-probe.py`), warm page cache, shared machine. Raw JSON:
`docs/research/native-performance-baseline/30-33-*.json`.

| operation | TS baseline (Bun) | native `bin/inbox` | delta |
| --- | --- | --- | --- |
| `inbox list` wall p50 (n=40) | 276 ms | 19 ms | ~14× faster |
| `inbox list` wall p95 | 355 ms | 36 ms | ~10× |
| `inbox list` max RSS (top-level, n=12) | 24 096 KB | 6 592 KB | ~3.7× smaller |
| `inbox capability` p50 (n=40, zero-I/O canary) | — (n/a baseline) | 15 ms | vs `bun -e 0` floor 24 ms |
| TUI first_byte p50 (n=12) | 50 ms | 15.7 ms | ~3× |
| TUI data_usable p50 | 344 ms | **17.1 ms** (p95 61.1) | ~20× |
| TUI pgid peak RSS p50 | ~48 MB | ~7.7 MB | ~6× |

Notes:

- `inbox list` p99 showed one 418 ms outlier under shared-machine load;
  p50/p95 are the stable signals per the baseline doc's own guidance.
- TUI numbers are post-fix (the `terminal.clear()` removal in §3.3);
  the pre-fix probe measured data_usable ≈ 2015 ms uniformly (the DSR
  stall), which is why that one-line-class fix matters beyond the
  probe: any terminal that does not answer `ESC[6n` would have eaten a
  flat ~2 s on every launch.
- Interactive key handling was exercised once via `tui-probe.py
  --advance-*`: Enter at ~230 ms opened the item detail screen (PTY
  output grew 1056 → 5440 bytes, clean exit). Full keymap coverage and
  the screenshot/video + independent visual review required by the
  acceptance criteria remain for human acceptance — this is why the PR
  stays Draft.
- The Rust TUI still draws every loop iteration (100 ms poll); output
  volume is small (≈1 KB/run in the probe) but a dirty-check is a
  possible follow-up, not a regression vs the TS renderer's behavior.

## 6. Known limitations / follow-ups

- **macOS arm64 binary only.** `platforms = ["macos"]`; Linux/Windows
  need verified builds (CI cross-compile or per-platform commits) before
  widening the manifest — ADR-0035 covers the distribution model.
- `watch`/`watch-pr` are long-running; contract-tested but not
  soak-tested against a live forge in this ticket.
- The committed `bin/inbox` must be rebuilt and re-committed on every
  source change (`cargo build --release -p inbox && cp
  target/release/inbox plugins/inbox/bin/inbox`); there is no CI gate
  for binary freshness yet — a `cargo build --locked` + `cmp` check is
  a candidate follow-up.
- `packages/tui` (TS) remains for the other plugins; `crates/tui` is
  currently a safety-helper crate only — the app-shell extraction waits
  for a second native consumer per ADR-0036.

## 7. Rollback

The TS implementation is intact at `0680de0~1` (`d5d74ce`). To roll a
user installation back: `herdr plugin install
rebuildup/hoxay-plugins/plugins/inbox --ref <previous-release-sha>`
(managed installs keep per-generation checkouts; running processes keep
their old files). Plugin state (`state.json` v2) is format-compatible
in both directions — verified by the TS-written-state fixture test — so
no state migration is needed either direction.
